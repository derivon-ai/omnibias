# Operator coverage matrix

Generated by `scripts/generate_coverage_matrix.py` from `docs/coverage/matrix_jax.json`, `docs/coverage/matrix_torch.json`. Every cell builds a small problem, asks the planner to serve it, evaluates the planned program and compares the value with a dense autodiff oracle written in the generator (nested `hessian` traces of the model's own forward pass, `jacfwd`/`jacrev` Jacobians of the residual vector), so no derivative formula of the package is involved. A cell whose relative error exceeds 1e-08 is a `mismatch` and fails the generator.

| status | meaning |
|---|---|
| structured | a chain program served it: projected, forward Laplacian, polylaplacian, Woodbury or stream Gram |
| reduced | a generic exact engine served a model that is not a dense chain, along `min(rows, columns)` directions of its first-layer products (the subspace programs); exact, but not a chain program |
| fallback | a generic exact engine served it with no reduction (nested autodiff or Taylor-mode jets); when the engine is the dense definition itself, the oracle agrees by construction |
| composed | built from calls of structured programs |
| refused | the planner refused it and said why; the reason is in the footnote |
| not_provided | the package has no program for it; the footnote names the route that exists |

A model is a *dense chain* when it is `dot -> bias -> activation` repeated and an affine readout; a literal scale such as the `w0` of a SIREN layer is folded into the weights. Skip connections, gates, attention, element-wise reads of the input and hard-boundary masks are not chains. The subspace programs apply when the input enters the model only through products with parameter matrices (for example `x @ W`), so that every input derivative lies in the row space of the stacked matrices; any other read of the input refuses with the operation that reads it.
